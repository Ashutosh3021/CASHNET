# Data Collection Summary — CASHNET ML Pipeline

This document summarizes the data collected for the three model workstreams (182, 183, 184),
their structure, and their relevance to the downstream machine-learning models. All raw source
data lives under each directory's `DATA`/`data` folder; runtime-downloaded reference corpora
live under `*/DATA/external/` and `*/data/external/` (regenerated by the fetch notebooks and
intentionally excluded from version control).

---

## 1. Model 182 — Crypto / VASP / Cross-Border Investigation

### 1.1 Source datasets (`182/DATA/`)
Seven case-type families, each split into 10–16 JSON batch files:

| Sub-folder | Batches | Grain |
|---|---|---|
| `cross_border_cases` | 10 | Cross-border crypto-fraud cases |
| `crypto_investigation_cases` | 10 | Investment-scam investigations |
| `legal_requests` | 10 | SAHYOG / legal disclosure & freeze requests |
| `ransomware_cases` | 10 | Ransomware-related investigations |
| `vasp_racking` | 16 | VASP tracking / attribution attempts |
| `vasp_responses` | 13 | Exchange KYC / freeze responses |
| `wallet_history` | 12 | Wallet transaction histories |

**Representative record schema** (`cross_border_cases/batch_001.json`):
```json
{
  "sahyog_case_id": "SAH-2025-12-03-635",
  "case_type": "cross_border_crypto_fraud",
  "investigation_details": { "agency": "...", "officer_name": "...", "badge_number": "..." },
  "international_coordination": { "countries_involved": [...], "interpol_case_id": "..." },
  "target_wallets": [ { "wallet_address": "...", "blockchain": "bitcoin", "priority": "CRITICAL" } ],
  "case_notes": "..."
}
```

**Reference `OUT` examples** (hand-authored target formats, not per-record labels):
`Complaint_report.json`, `O1.json` (wallet→VASP attribution + legal-request generation),
`O2_dashboard.json`, `Req_Router.json` (multi-VASP routing + Interpol/MLAT),
`SLA.json` (performance dashboard), `SUMMERY.txt`.

### 1.2 Externally fetched corpora (`182/DATA/external/`)
- **SNAP Bitcoin OTC & Alpha signed trust networks** (`bitcoin_otc_trust.csv.gz`,
  `bitcoin_alpha_trust.csv.gz`): directed edges `(source, target, rating ±1..10, time)` —
  graph features for clustering/attribution.
- **Elliptic AML dataset** (`elliptic_aml/`): `elliptic_txs_features.csv` (~689 MB, 166 features
  per transaction), `elliptic_txs_edgelist.csv` (transaction graph), `elliptic_txs_classes.csv`
  (illicit / licit / unknown labels) — the only **labeled** fraud signal in this workstream.

### 1.3 Relevance to Model 182
- Wallet→VASP **attribution** and **clustering** → graph embeddings over SNAP + Elliptic edges.
- **Cross-border routing** (which exchange/jurisdiction to query) → country + VASP features.
- **Compliance monitoring / SLA dashboards** → case lifecycle fields.
- **Gap:** `OUT` targets are illustrative; supervised training needs labels derived from
  Elliptic (illicit flag) and/or human-annotated (correct VASP per wallet).

## 2. Model 183 — Complaints / Support / Transactions

### 2.1 Source datasets (`183/DATA/`)
| Family | Files | Size | Content |
|---|---|---|---|
| Complaint datasets | `BM_type_generated.json`, `PHISING_generated.json`, `TBF_generated.json`, `TECH_issue_generated.json` | 3.7–5.7 MB | Categorized fraud complaints (banking misuse, phishing, tech-support, etc.) |
| Support reference | `Labled_data_generated.json` (3.2 MB), `Past_data_generated.json`, `Sahyoog_generated.json`, `Wallet_db_generated.json` | 14 KB–3.2 MB | Prior cases, SAHYOG linkage, wallet DB |
| Transaction datasets | `BLOCK_chain_trnsdata_generated.json` (~12 MB), `BTC_trns_generated.json`, `tron_generated.json` | 4.4–12 MB | On-chain transaction records |

**Reference `OUT` examples:** `BC_attri_res.json`, `Dashboard.json`,
`Report_to_investigate.json` (crypto-fraud attribution report), `Risk_and alert.json`,
`SUMMERY.txt`, `Wallet_res.json`.

### 2.2 Externally fetched corpora (`183/DATA/external/`)
- **CFPB consumer complaints** (`cfpb_complaints.csv.zip` → `complaints.csv`, ~638 MB): real,
  labeled complaint narratives with product/sub-product, issue, and resolution — strong
  supervised text for complaint classification.
- **Banking77** (`banking77_categories.json`, `banking77_train.csv` 10,003 rows,
  `banking77_test.csv` 3,080 rows): 13,083 online-banking queries labeled with 77 intents —
  intent-detection training for the support/Routing layer.
- **Credit-card fraud** (`creditcard_fraud/creditcard.csv`, ~284 MB): 284k labeled transactions
  (PCA features + `Class`) — transaction-level fraud classifier.

### 2.3 Relevance to Model 183
- **Complaint classification / routing** → CFPB + Banking77 (text → category/intent).
- **Risk & alert generation** → creditcard fraud classifier + complaint severity.
- **Investigation report generation** → structured fill from classified complaints + txn lookups.
- **Gap:** Source complaint JSONs are synthetic/LLM-generated; CFPB/Banking77 provide the real,
  labeled signal that makes supervised training viable.

## 3. Model 184 — Banking / ATM / Geospatial

### 3.1 Source datasets (`184/data/`)
- **Reference** (`data/reference/`): `banks.json`, `cities.json`, `fraud_types.json`,
  `osm-atms/` (per-city ATM GeoJSON: ahmedabad, bengaluru, delhi, gurugram, hyderabad, mumbai).
- **Synthetic banking** (`data/synthetic/bank/`): `account_registry.json`, `atm_withdrawal_links.json`,
  `bank_transactions.csv/.json` (~12.9 MB), `complaint_transaction_links.json`, `transaction_graph.json`.
- **Synthetic complaints** (`data/synthetic/complaints/`): `BM_C.json` (34.9 MB), `complaint.json`
  (27.5 MB), `complaint_account_registry.json`, `complaint_metadata.json`.
- **ATM corpus**: `data/synthetic/ATM.json` (13.4 MB).
- **Generators**: `scripts/` (banking, complaints, geospatial) — data is fully reproducible.

**Reference `OUT` examples:** `DASHBOARD.json`, `Full_report.json` (predictive withdrawal
intelligence), `PS1_output.json`, `RISK_hm.json`, `SampleAlerst.json`, `SUMMERY.txt`.

### 3.2 Externally fetched corpora (`184/data/external/`)
- **OSM ATM extracts** (`atm_delhi.json`, `atm_mumbai.json`, `atm_bengaluru.json`,
  `atm_hyderabad.json`, `atm_ahmedabad.json`, `atm_gurugram.json`): live ATM locations via
  Overpass API — refreshes/augments the synthetic geospatial layer.
- **CFPB consumer complaints** (same as 183) — complaint text for the banking layer.
- **Synthetic financial fraud transactions** (`synthetic_financial_fraud/`, Kaggle): labeled
  fraud/non-fraud transfers for withdrawal-pattern modeling.

### 3.3 Relevance to Model 184
- **Predictive withdrawal intelligence** (which city/ATM a fraudster will cash out) →
  transaction-graph + geospatial + historical pattern features.
- **Risk scoring & alerts** → fraud labels + mule-account patterns.
- **Dashboards** → aggregate metrics over complaints/transactions/ATMs.
- **Gap:** Core data is synthetic; external CFPB + synthetic-financial-fraud + live OSM give the
  realism and labels needed for credible accuracy.

## 4. Cross-Cutting Observations
- Each `OUT` folder contains a small set of *format/contract* examples, not a large labeled
  training set. Training therefore relies on the **externally fetched labeled corpora**
  (Elliptic, CFPB, Banking77, creditcard fraud, synthetic financial fraud) plus labels derived
  from them.
- Data spans three modalities: **tabular/transactional** (Elliptic, creditcard, bank txns),
  **graph** (SNAP trust, transaction graphs, VASP links), and **text** (complaints, intents).
- Outputs for all three models converge on the same shape: a **risk/attribution object** +
  a **dashboard/summary** + a **routing/action list** — which is what the modular pipeline
  (Section 5 of `plan.md`) must produce into each `OUT` folder.

## 5. Storage Layout (post-fetch)
```
182/DATA/external/  -> bitcoin_otc_trust.csv.gz, bitcoin_alpha_trust.csv.gz, elliptic_aml/
183/DATA/external/  -> cfpb_complaints/, banking77_*.csv/json, creditcard_fraud/
184/data/external/  -> atm_*.json, cfpb_complaints.csv.zip, synthetic_financial_fraud/
```
These folders are git-ignored; they are produced locally by the fetch notebooks. The repo
carries only code, notebooks, schemas, and this documentation.
